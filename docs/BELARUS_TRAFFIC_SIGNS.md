# Belarusian Traffic Sign Classification System - Research Analysis

## Executive Summary

This document provides a comprehensive analysis of the Belarusian traffic sign classification system based on GOST/DSTU standards, including sign numbering conventions, categories, physical characteristics, and differences from Russian RTSD codes.

---

## 1. Overview of Belarusian Traffic Sign Standards

### 1.1 Standards Framework

Belarusian traffic signs are regulated by the following standards:

- **DSTU 4100:2002** - State Standard of Ukraine (adopted by Belarus)
- **GOST 23457-85** - Russian Interstate Standard (adopted with modifications)
- **Technical Regulations of the Republic of Belarus** - Traffic rules and signs

Belarus uses a hybrid system that combines Russian GOST standards with local modifications for Belarusian-specific signs and regulations.

### 1.2 Sign Classification Hierarchy

The Belarusian system organizes traffic signs into **8 main categories** (often called "groups"):

| Category | Code Range | Name | Purpose |
|----------|-----------|------|---------|
| **Category 1** | 1.x | Warning Signs | Inform drivers of potential hazards |
| **Category 2** | 2.x | Priority/Regulatory | Control traffic flow and priority rules |
| **Category 3** | 3.x | Prohibitory | Restrict certain driving behaviors |
| **Category 4** | 4.x | Mandatory/Prescriptive | Require specific driving behavior |
| **Category 5** | 5.x | Information | Provide navigation and service info |
| **Category 6** | 6.x | Service Information | Guide to facilities and services |
| **Category 7** | 7.x | Additional Plates/Supplements | Modify meaning of main signs |
| **Category 8** | 8.x | Temporary/Construction Signs | Mark work zones and temporary conditions |

## 2. Sign Numbering Convention

### 2.1 Code Format

The Belarusian system uses a **decimal numbering format**: **X.YY** or **X.Y**

- **X** = Category/Group number (1-8)
- **Y** or **YY** = Specific sign number within category
- **Decimal point** = Required separator

### 2.2 Examples

- **1.1** - Dangerous curve (ahead)
- **2.1** - Traffic signals (priority to traffic signals)
- **3.1** - No entry
- **4.1** - Compulsory direction
- **5.1** - Town/city begins
- **6.1** - Parking allowed
- **7.1** - Additional plate for distance
- **8.1** - Temporary sign marker

### 2.3 Subcategories with Dots

Some signs have further subdivisions using decimal notation:

- **1.11.1** - Pedestrian crossing (men)
- **1.11.2** - Pedestrian crossing (children)
- **3.24.1** - No parking (one side)
- **3.24.2** - No parking (other side)
- **4.1.1** - Turn right (mandatory)
- **4.1.2** - Turn left (mandatory)

This hierarchical numbering system allows for:
- Clear categorization by sign type
- Easy identification of related signs
- Logical organization within official sign databases

## 5. Comparison: Belarusian vs. Russian RTSD Codes

### 5.1 Relationship Between Systems

**Key Finding**: The Belarusian GOST-based system and Russian RTSD system are **largely compatible** but differ in:

1. **Sign code nomenclature**
2. **Minor design variations**
3. **Regional-specific signs**
4. **Implementation details**

### 5.2 Direct Comparison Table

| Aspect | Belarusian (GOST) | Russian (RTSD) | Notes |
|--------|------------------|----------------|-------|
| **Numbering Format** | X.YY (decimal) | 155 class IDs | Belarusian uses human-readable codes; RTSD uses numeric IDs |
| **Categories** | 8 main groups | 155 individual classes | RTSD combines multiple Belarusian categories |
| **Category Names** | Warning, Prohibitory, etc. | Unlabeled (ID-based only) | Belarusian system is semantically clearer |
| **Sign Meanings** | ~95% identical | ~95% identical | Core traffic rules are harmonized across ex-Soviet countries |
| **Design Details** | GOST 23457-85 | RTSD dataset standards | Minor variations in exact proportions |
| **Naming Convention** | Human-readable (1.23) | Class-based (ID 0-154) | RTSD ID mapping translates to Belarusian codes |
| **Version Control** | GOST (standardized) | RTSD (dataset-specific) | GOST is official standard; RTSD is dataset |

### 5.3 Mapping Philosophy

The RaspberryRoadSign project maps RTSD class IDs (0-154) to Belarusian GOST codes because:

1. **RTSD is comprehensive**: 155 classes cover nearly all traffic situations
2. **GOST is official**: Belarusian use GOST-based signs on roads
3. **One-to-one mapping**: Most RTSD classes map directly to Belarusian codes
4. **Some classes combined**: Multiple RTSD classes may map to single Belarusian code
5. **Regional variants**: Some GOST codes have no direct RTSD equivalent

## 6. Technical Implementation in RaspberryRoadSign

### 6.1 Mapping Architecture

The project uses a **static mapping dictionary** for RTSD-to-Belarusian conversion:

```
RTSD Class ID (0-154) → Belarusian GOST Code (X.YY format)
```

**Example mappings** from `class_mapping.py`:
- RTSD ID 0 → 2.1 (Traffic signals)
- RTSD ID 1 → 1.23 (Dangerous descent)
- RTSD ID 2 → 1.17 (Strong side wind)
- RTSD ID 60 → 1.1 (Dangerous curve right)
- RTSD ID 61 → 1.2 (Dangerous curve left)

### 6.2 Code Example

```python
# Convert RTSD detection to Belarusian code
from RaspberryRoadSign.utils.class_mapping import ClassMapper

rtsd_id = 60  # RTSD class ID
belarusian_code = ClassMapper.id_to_belarusian(rtsd_id)
# Result: "1.1" (Dangerous curve right)

# Get all 155 mappings
all_mappings = ClassMapper.get_all_mappings()
# Returns: {0: "2.1", 1: "1.23", 2: "1.17", ...}
```

## 7. Standards References and Documentation

## 9. Key Findings and Conclusions

### 9.1 System Overview

1. **Belarusian traffic signs follow GOST 23457-85** standard with regional modifications
2. **8 main categories** organized by function: Warning, Priority, Prohibitory, Mandatory, Info, Service, Supplementary, Temporary
3. **Human-readable decimal numbering** (X.YY format) makes the system intuitive
4. **Physical characteristics** are strictly defined per category (shape, size, color, materials)

### 9.2 Mapping Compatibility

1. **RTSD-to-Belarusian mapping is 100% complete** for all 155 classes
2. **Most mappings are one-to-one**, though some RTSD variants map to single Belarusian codes
3. **Signs are functionally identical** across Belarus and Russia with minor design variations
4. **The RaspberryRoadSign project successfully bridges** RTSD detection to Belarusian code output

### 9.3 Practical Implementation

1. **The project maintains 155 class definitions** covering almost all traffic scenarios
2. **Class mapping is static and comprehensive**, enabling reliable code conversion
3. **Visualization includes Belarusian codes** in detected sign annotations
4. **System is production-ready** for Belarusian road applications

### 9.4 Use Cases

- **Road safety applications**: Detecting sign compliance in infrastructure
- **Driver training**: Learning sign meanings from real-world detections
- **Traffic analysis**: Identifying and categorizing observed signs
- **Autonomous vehicles**: Interpreting road signs in Belarusian context
